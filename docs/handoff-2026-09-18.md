# Handoff to local OMP agent

This bundle is a **work-in-progress handoff**, not a claim that the extension is verified or production-ready.

## Goal

Finish and safely install a provider-agnostic adaptive model router for OMP.

The intended behavior is:

- Keep inference/retry/auth/credential rotation/fallback inside native OMP.
- Use a thin OMP extension only for proactive route selection before new work.
- Availability/health sources: OMP usage first, CodexBar second, recent runtime health/cooldowns third.
- A fresh runtime 429/quota/Retry-After is a hard temporary veto for that concrete route/credential.
- Route states: `AVAILABLE`, `DRAINING`, `COOLDOWN`.
- Tier order:
  - Frontier: Fable subscription → Astra subscription → Opus subscription → healthy opus-ish subscription → strong subscription flash → strong Chinese → best free → graceful drain.
  - Balanced: Sonnet 5 subscription → Luna subscription → Chinese flash PAYG → free Chinese flash → best available → healthy free → graceful drain.
  - Small: cheapest suitable subscription → cheapest suitable flash → healthy free fast → graceful drain.
- Within an eligible class: **cheapest healthy route → cheapest available route → best available route**.
- When shared quota pressure increases, stop admitting new work in this order: frontier first, then balanced, then small. Do not kill in-flight work.
- OpenRouter Data API can reorder models **inside an allowed class only**; it cannot promote a model across tier/class boundaries.
- Reuse the OpenRouter API key already resolved by OMP for both inference and Data API. Do not introduce a second stored key and do not scrape OMP credential databases.
- Provider inventory must come dynamically from OMP. Adding/removing providers must not require code changes.
- Free-route probing is event-driven and quiet: after a real free-route failure, check at most two backup free routes, cache health, and avoid periodic probe spam.
- Extension must fail open: if it breaks or telemetry is missing, leave model choice to native OMP rather than stopping work.
- Never log or persist API keys, OAuth tokens, emails, or raw credential identifiers.

- Preserve native OMP retry/fallback/credential rotation. The extension is only a proactive policy layer.

- Health precedence: OMP usage > CodexBar > local observed health; runtime 429/quota/Retry-After is an immediate temporary veto.

Your job:

## Suggested shell start

## Rollback principle

Before installation the local agent must create a backup of `~/.omp/agent/config.yml`.
The extension should remain independently disable-able/removable so native OMP fallback remains the safety net.
