# Roadmap

Ordered. Each item links to the evidence that put it here. Do not start an item whose predecessor is open unless the human says so.

## Open

### 1. BUG C — context loss on model switch — ROOT CAUSE PROVEN, repair is outside this repo
**Status:** investigated across 7 cases with provider-payload tracing (`tools/context-tracer/`). The hypothesised loss (switch resets/omits history) **does not reproduce** for direct switch, `pi.setModel`, native 429 fallback, cross-provider, 1M→32k shrink, or Multica same-file re-spawn. The real loss is **OMP OpenAI remote compaction**: on a Responses-API provider OMP stores provider-native `replacementHistory` and a one-line placeholder summary; after a switch to any non-Responses model the placeholder is all the new model sees. Proven in a real 3,300-entry session (4 remote compactions, 250–300k tokens each → 933-char placeholder). See `docs/investigations/bug-c-context-loss-root-cause.md`.
**Fix boundary:** OMP config or OMP core — **not adaptive-router**. The config lever was renamed upstream: `compaction.remoteEnabled` no longer exists in 18.2.6 ("Replaced `compaction.strategy` and `compaction.remoteEnabled` with an ordered `compaction.methodOrder` preference list"), so the mitigation is `compaction.methodOrder` without `"remote"` — applied at user level 2026-09-19.
**Router-side guard: DONE** (see Done → "remote-compaction hold"). What stays open is the upstream repair: when a remote compaction exists and the switch target cannot replay it, OMP should generate a portable summary from `replacementHistory` at switch time instead of substituting the placeholder.

### 2. Hermes-side, not this repo: `hermes update` silently un-integrates OMP
Every Hermes-core edit the bridge needs is scripted in `~/.hermes/plugins/model-providers/omp/reapply_omp_patches.py`, and `hermes update` wipes all of them. On 2026-09-19 `--check` reported **all 15 patches missing** — which is why Multica's picker showed no OMP models at all (the ACP catalog was down to the current-model fallback row). Reapplying restored it to 1245 rows, 1173 of them `omp:*`, every `pmr/*` selector included.
The integration therefore depends on a human remembering to run that script after each update. Options, all Hermes-side: a post-update hook that runs it, or upstreaming the overlay so no patching is needed. Until then, after any `hermes update`: `python3 ~/.hermes/plugins/model-providers/omp/reapply_omp_patches.py --check`.

### 3. Desktop renderer patches need a rebuild
`reapply_omp_patches.py` also patches `apps/desktop/src/**` (model labels, visibility, catalog menu). Those are source edits: they only reach the Hermes desktop UI after `cd apps/desktop && npm run pack`. Not run on 2026-09-19 — the Multica path does not depend on it, the desktop UI does.

## Done

- **Deploy lock** (was open item 2) — `install.sh`/`uninstall.sh` acquire `$(omp config path)/extensions/.adaptive-router-deploy.lock` by atomic `mkdir`, write `meta.json` (`pid`/`session`/`started_at`), reclaim a lock whose pid is dead or whose age exceeds 600 s, and release via `trap ... EXIT` only when the run created it. Five tests in `scripts/install.test.sh`, each mutation-proved. Found on the way: under macOS bash 3.2 a bare `[[ … ]]` assertion does **not** trip `set -e` unless it is the script's last statement, so the pre-existing assertions in that file were silent no-ops — all standalone assertions are now POSIX `[ … ]`. Live-proved by the install that deployed the remote-compaction hold (lock acquired, released, installed hashes equal to the repo tree).
- **429 / fallback and PAYG-vs-subscription** (was open item 3) — both claims CONFIRMED with mutation-proved tests (`extension/tests/payg-vs-sub.test.ts`) and a report (`docs/investigations/finding-429-payg.md`). A healthy subscription always beats PAYG; a *draining* subscription losing to a healthy PAYG route is the two-pass ladder working as designed (`ranking.ts:182-183`), not a violation. Native fallback carries full history: the router's retry hooks touch only route-health bookkeeping and `shouldRouteBeforeAgentStart` blocks `setModel` for the whole retry, so OMP core owns the continuation end to end.
- **`docs/design.md` DRAINING drift** (was open item 4) — the section claimed a CodexBar pace forecast can independently drive DRAINING. Rewritten to the two mutually-exclusive paths `health.ts` actually implements, with the I2 override stated and every claim traced to a line (`health.ts:54-65`, `102-111`, `128-129`, `148-153`, `163-169`); the misleading `claude-sonnet-5 DRAINING quota pace` example is now an I2 demonstration.
- **Host integration — all four paths answered** (was open item 5) — see `docs/investigations/host-integration-matrix.md`. `omp` directly, `multica → omp`, `paseo → omp` and `multica → hermes → omp` are all governed; the last one's earlier "cannot be governed" verdict was wrong and is corrected there with a live probe (`tools/hermes-path-probe/probe.py`). The final open row is closed too: no Multica launch passes `--no-extensions` — 647 real `omp` launches across every rotated daemon log show only two argv shapes, both without it, and the flag string in the daemon binary belongs to the Claude flag cluster (`docs/investigations/finding-multica-no-extensions.md`).
- **Hermes ⇄ OMP bridge fidelity — all four rows closed** (was open item 6). Plugin-side, in `~/.hermes/plugins/model-providers/omp/`:
  - **Model pinning.** `_pin_model` split the id on the first `/` and swallowed every error, so Multica's prefixed picker ids (`omp:anthropic/claude-fable-5-1`, `omp:openai-codex/gpt-5.6-luna` every 30 min from the hotline cron) produced provider `omp:anthropic` → `Model not found` → the turn silently ran on OMP's persisted current model (`kilo/kilo-auto/efficient`). Now the host prefix is stripped, a refusal raises, an acked-but-unmoved switch raises, and a normalised id warns. `test_model_pin.py`, 4/4 behavioural tests red against the pre-fix file.
  - **Tool calls.** OMP's own tool work now rides Hermes' tool rail instead of being flattened into `[omp:bash]` prose: the profile opts in with `wants_agent_handle`, the core hands `_hermes_agent` to that profile only, and the client reports `tool.started`/`tool.completed` through `agent.tool_progress_callback` — the callback both the ACP adapter (Multica) and the desktop gateway install. `delta.tool_calls` stays `None`, so Hermes still never re-executes finished work. Live: a real `bash` tool produced `tool.started bash args={'command': 'echo …'}` + `tool.completed … is_error=False` with no marker in the transcript. `test_tool_rail.py` (11 tests) and core `tests/agent/test_provider_agent_handle.py` (4 tests, red-proved).
  - **Streaming.** Order, boundaries and interleaving with tool activity verified (`test_stream_fidelity.py`). One real bug found and fixed: `__next__` checked `_failure` only before blocking on the queue, so a consumer parked in `queue.get()` saw the producer's `__done__` first and raised a bare `StopIteration` — an OMP-side failure became a clean, EMPTY answer while the non-streaming path raised. Both paths now agree.
  - **Reasoning.** Correct as written: `thinking_delta` goes to `reasoning`/`reasoning_content` only, never leaks into `content`, on both paths.
  - **Termination.** `finish_reason` is no longer hard-coded `"stop"`: OMP's `message.stopReason` is mapped to the OpenAI vocabulary (`max_tokens`/`truncated` → `length`, `tool_use` → `tool_calls`), and an aborted/cancelled/errored turn raises instead of masquerading as a completed answer.
- **Remote-compaction hold** (BUG C router-side guard) — `extension/compaction-guard.ts`: the router refuses its own switch when the branch's newest compaction is `method: "remote"`, the session is on a Responses-API provider, and the target cannot replay it (different provider, or not a Responses API). It announces `[omp:pmr] switch held: …` once per session and fails open on missing metadata. 8 tests (`extension/tests/compaction-guard.test.ts`) including the hook-level wiring; 5/8 red under an inverted guard.

- **`pmr/*` selectors** — the virtual provider is `pmr`, and the picker offers four tiers: `pmr/frontier`, `pmr/balanced`, `pmr/small` (cheap and fast, paid rungs included) and `pmr/free` (free-only by contract, never spends). Switch markers read `[omp:pmr]`. Upper-case ids were verified to resolve, but lower case matches every other OMP provider id, with `PMR: …` as the display name.
- **First managed turn no longer waits for telemetry** — `before_agent_start` used to await `omp usage` + the CodexBar CLI (28–31 s live). Refreshes are scheduled instead, and the normalized snapshot is persisted in `state.json` (15-minute bound) so a fresh process — every Multica run — routes from last-known data. Live: 7 s including the answer. `first-turn-latency.test.ts`.

- **CodexBar window scope** — allowance windows (with a reset) no longer veto a provider whose prepaid balance still has capacity, a spent balance no longer borrows an allowance's reset date, and a pace forecast only counts for the window that carries capacity. Closes FOLLOWUP-T1 and the exhaustion half found live on kilo. Invariants N5/N6; `codexbar-windows.test.ts`, `codexbar-pace-scope.test.ts`. See `docs/investigations/finding-codexbar-window-collapse.md`.

- **BUG D** — healthy Sonnet subscription bypassed by CodexBar weekly pace forecast. A fail-closed `before_provider_request` guard aborts the turn if a request ever reaches the virtual provider (live-verified: 0 auto-retries vs 10 unguarded). 85/85 unit tests + differential replay; live-verified managed cold start and manual opt-out. Spec: `docs/spec-virtual-model-routing.md`; plan: `docs/superpowers/plans/2026-09-19-virtual-model-routing.md`.
